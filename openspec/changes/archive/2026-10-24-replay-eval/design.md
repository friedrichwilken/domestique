# Design

## Context

See proposal.md. Depends on `claims-and-prediction-loop`.

## Goals / Non-Goals

**Goals:** an eval that runs in under a minute on fixtures and is deterministic.
**Non-Goals:** statistical rigour beyond a planted effect; real data.

## Decisions

- **Replay cursor enforced by a data-access wrapper**, not by trusting the predictor. The predictor gets a view object that refuses future dates.
- **Synthetic season generated by code with a fixed seed**, committed as files so diffs are reviewable. Alternative: hand-written. Rejected: 84 days is too many to hand-write honestly.
- **Loop on/off switch** as a harness flag so the planted-effect scenario is one command.

## Risks / Trade-offs

- A synthetic season can only validate that the loop learns what was planted. Real validation needs an athlete's own history run locally, outside the repo.
